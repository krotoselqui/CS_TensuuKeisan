# 現行仕様と互換性の基準

確認日: 2026-09-06。動作の基準はリファクタリング差分を破棄した `a1646b1` のソース。型・ファイル名は、その後の `MahjongScoreTrainer` への改名とデータ型のファイル分離を反映している。

この文書は実装から読み取れる現行動作と、今後の変更で守る条件を記録する。麻雀ルールの網羅的な正当性や、全入力での動作を検証済みという意味ではない。疑わしい動作は既知の課題として扱い、不具合を仕様として固定しない。

## 目的と範囲

麻雀の点数計算を練習するため、手牌の問題と解答をまとめて生成する。対局進行、オンライン機能、手入力した手牌の採点画面、ドラ設定は対象外。`Main` はコマンドライン引数を解釈せず、コンソールから入力を受け取る。

## 入力

| 項目 | 受理する値 | 現行の扱い |
| --- | --- | --- |
| 問題数 | `int` の範囲内で 1 以上 | 受理するまで入力を繰り返す |
| シード | `-1` または 0 以上の `int` | `-1` は時刻由来の乱数。0 以上は `Random(seed)` |
| 表示形式 | `0` または `1` | 0 は専用フォント向け、1 は通常の牌記号 |

不正文字列・範囲外の入力は `ReadOptions` 内の `TryParse` で判定して再入力になる。EOF も従来どおり再入力になり、正常終了は実装されていない。これは今後改善する対象であり、無限の再入力を推奨する仕様ではない。

## 生成から解答まで

1. `Program.GenerateProblems` が `YakuWeights` の役番号と重みから対象役を抽選する。34 項目があり、四槓子の重みは 0。
2. `Program.makeYaku` が残り牌枚数を使って手牌・和了牌・副露を生成する。通常形に加え、七対子・国士無双・九蓮宝燈系の専用分岐を持つ。
3. 同じ手牌を東場の「東家ツモ、東家ロン、西家ツモ、西家ロン」の順で採点する。
4. `HandEvaluator.Yaku_Keishiki` が役と採点結果を返す。生成時に狙った役と、実際に成立する役の集合は同一とは限らない。
5. 問題と解答を保存し、4 条件で成立した役の回数を集計する。

役を追加・削除するときは、番号・名前・重み・生成分岐・判定・飜数・表示の対応をまとめて確認する。名前テーブルの存在だけで対応済みとはしない。

## 内部データの契約

| 値 | 意味 |
| --- | --- |
| 物理牌 ID `0～135` | 同一牌 4 枚を区別する ID |
| 牌種 `1～34` | 萬子 1～9、筒子 10～18、索子 19～27、字牌 28～34 |
| 牌種 `0` | 配列の未使用領域等。和了牌として有効ではない |
| 色 `0～3` | 萬子、筒子、索子、字牌 |
| 風 `0～3` | 東、南、西、北。字牌の牌種 28～31 とは別 |
| 面子種別 `0～6` | 雀頭、暗刻、明刻、暗槓、明槓、暗順、明順 |

物理牌 ID から牌種への変換は `tileId / 4 + 1`。役番号は役名テーブルの添字であり、牌種と混同しない。

`WinningHandData.tehai` は和了牌を含む非副露側の牌配列で、`agarixs` は和了牌の種類を別途示す。同じ牌を和了牌だからといって再加算しない。副露等は `furotehai` と `furotype` で保持する。暗槓はこの領域に格納されるが、門前を崩す明刻・明槓・明順とは区別する。

生成を変更するときに確認する条件:

- 有効牌は 1～34、全領域を合わせた同一牌の枚数は 4 以下。
- 和了時の総枚数は槓を含めて `14 + 槓数`。`agarixs` を別の 1 枚として数えない。
- 通常形・七対子・国士無双をそれぞれの構造で確認する。
- 暗順（種別 5）を副露として処理しない。空き領域や前の問題の値を持ち越さない。
- 同じ手牌を 4 条件で評価しても、先の採点が後の入力を壊さない。

## 採点

`HandEvaluator.cs` に面子分解、和了位置の列挙、役の判定、役の重複整理、符・飜の計算がある。採点候補は `scoresum` の大小で選択する。

`ScoreResult` は `fan`、`fu`、`ykm`、`scoresum`、`other_pay`、`dealer_pay` を持つ。`ykm` が真なら `fan` は役満倍率を表す。`KIRIAGE` は偽で、13 飜以上を役満相当として計算する処理がある。個々の役満の倍率は一般ルールから推測せず、役フラグと集計処理を確認する。

立直・一発・ドラ等の名前は定義されているが、それらの状況を入力する機能はない。任意の役フラグ配列を外部から渡しても正しく採点できるという契約は設けない。

## 出力

3 ファイルは実行時のカレントディレクトリに Shift_JIS で保存し、同名ファイルを上書きする。

| ファイル | 契約 |
| --- | --- |
| `question.txt` | 1 問 1 行。非副露側から和了牌 1 枚を分けて表示し、副露を付記。通常形式は `[問題番号]` 付き |
| `answer.txt` | 1 問 1 行。`[問題番号]` と 4 条件の点数を ` / ` で区切る |
| `answer_yaku.txt` | 問題番号の行と、4 条件それぞれの符・飜または役満倍率・成立役の行 |

親ツモは `支払額∀`、子ツモは `子の支払額-親の支払額`、ロンは放銃者の支払額を表す。牌の横向き表現も表示形式別テーブルに従う。

終了時の役別集計は、抽選回数ではなく 4 条件それぞれの成立回数。同じ問題が複数の役・条件で加算される。コンソールに進捗を表示し、最後にキー入力を待つため、現在の実行確認は対話コンソールで行う。

出力失敗時の一括取り消しや一時ファイル経由の置換は実装されていない。エラー途中にはファイルの一部だけが残る可能性がある。

Main が開いたファイルは `using` で所有し、正常時・例外時とも解放する。これは Main 整理時に追加した資源管理の改善である。`GenerateProblems` に外部から渡す `TextWriter` は借用し、閉じない。出力例外は呼び出し元へ伝播する。

`GenerateProblems` は設定・乱数源・3 個の writer・任意の進捗通知を受け取る。進捗は各問題の生成前に 0 始まりの番号と全問題数で通知する。戻り値は出題対象順の役別成立回数で、呼び出しごとに初期化する。未変更の `makeYaku` が静的設定を使うため、生成中だけ同じ乱数源と表示形式を設定し、`finally` で元に戻す。並行実行は対象外で、インスタンスへの完全な移行は別の段階とする。

## 互換性と受け入れ例

純粋なリファクタリングでは、同じ環境・問題数・シード・表示形式で生成した 3 ファイルの内容を変更前後で比較する。問題番号、条件順、空白・区切り、文字コードも対象とする。異なる .NET 実装・バージョン間の乱数列一致は保証しない。

以下は検証に用いる具体例。牌変換と `ScoreResult` の点数例は [CI の回帰検査](ci.md) に実装済み。生成結果は各 20 問、2 シード・2 表示形式で整理前の出力との比較を自動化している。

| 対象 | 入力・操作 | 期待結果 |
| --- | --- | --- |
| 再現性 | 同じ環境で問題数 10、シード 12345、形式 1 を 2 回生成 | 3 ファイルがそれぞれ一致 |
| 出力対応 | 問題数 10、形式 1 | 問題・点数解答が各 10 行、役詳細は各問題 4 条件 |
| 牌変換 | 物理牌 ID 0、3、4、135 | 牌種 1、1、2、34 |
| 子の点数計算 | `ScoreResult(1, 30, false, false)` | ロン 1000、ツモは子 300・親 500 |
| 親の点数計算 | `ScoreResult(1, 30, false, true)` | ロン 1500、ツモ 500 オール |
| 切り上げなし | `ScoreResult(4, 30, false, false)` | ロン 7700、ツモは子 2000・親 3900 |
| 満貫 | `ScoreResult(5, 30, false, false)` | ロン 8000、ツモは子 2000・親 4000 |

この点数例は符・飜から支払額への計算を確認するもの。手牌から符・飜を判定する正しさは、別途具体的な手牌例で検証する。

## 未検証・今後の課題

- 役ごとの生成が常に成立条件を満たすこと、全ての牌構成と符計算の網羅性。
- 役満の複合・倍率、同点候補の選択、役なし・不正な手牌を直接渡した場合の扱い。
- 生成時の再試行が必ず終了すること、大量出力時の所要時間。
- EOF と出力失敗時の利用者向け案内・終了方法。

これらを変更する際は、再現入力と期待結果を追加し、現行動作の説明と新しい仕様を同時に更新する。
